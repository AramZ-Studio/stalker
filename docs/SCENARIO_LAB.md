# 단일 데모와 상황 체험실

## 진입 구조

메인 메뉴는 게임 시작(일주일 생존), 상황 체험실, 설정, 종료입니다. 예전 첫날 밤·현관 전용·안내 시연은 메인 메뉴와 엔딩 메뉴에서 제거했습니다. 기존 회귀 검증을 위해 내부 코드와 명령행 테스트는 유지합니다. Esc로 메인 메뉴나 체험실 선택 화면을 닫아 이전 자유 시연에 진입할 수 없게 했습니다.

## 데모의 선택과 진행

분 단위 연출 시간표 대신, 생활 시간이 흘러야 날짜별 사건이 발생합니다. 정상 배송은 실제 주문이 있어야 오며, 업무·수면과 중단·재개는 같은 생활 시간선을 사용합니다.

| 날짜 | 주요 변화 |
| --- | --- |
| 1일차 | 정상 배송과 생활 계획. 치명적인 사칭 방문 없이 규칙을 익힘 |
| 2일차 | 번호를 못 읽거나 통화 중인 정상 배송, 이웃 우편물과 사각지대 정보 |
| 3일차 | 첫 사칭. 주문 번호를 알아도 물품과 행동에서 모순이 드러남 |
| 4일차 | 카메라에서 빠르게 사라져 문 옆에 남는 방문 |
| 5일차 | 일반 주문 도착이 두 시간 지연. 재고·업무·수면과 빠른 음식 배송의 선택 |
| 6일차 | 배달원의 올바른 물품 답변을 흉내 내는 사칭. 렌즈와 소리로 교차 확인 |
| 7일차 | 학습한 사칭과 실제 퇴장 이후 한 차례의 말없는 재방문 |

정해진 날짜에 모든 장면을 강제로 재생하지는 않습니다. 수면·업무 시각, 주문, 관찰과 회수 여부에 따라 방문과 단서를 경험하는 순서가 달라집니다. 보고 있지 않아도 잠금 상태를 무작위로 깨고 사망시키지는 않습니다. 외형이나 질문 하나만으로 항상 정체가 확정되지 않게 하되, 물품·퇴장·렌즈·근접 소리 같은 독립적인 확인 수단을 유지합니다.

시작 자금은 24,000원입니다. 비축식은 2끼 10,000원, 따뜻한 음식 15,000원, 카메라 14,000원, 첫 스프레이 18,000원입니다. 초기에 모두 구매할 수 없으며 업무로 마련할 수 있습니다. 기본 관찰만으로도 생존 가능합니다. 식사 최소 한 끼 규칙과 공복·정신력 관리, 7일차 자정 목표는 유지합니다.

물품은 3시간 내 회수하지 않으면 분실하고 환불하지 않습니다. 도착 안내와 휴대폰에서 기한을 알립니다. 5일차 지연은 주문 전에 해당 날짜 안내에서, 주문 후에는 도착 예정 시각에서도 확인할 수 있습니다. 이웃의 정보를 얻으면 기록에 남습니다. 추가 조건을 강요하지 않는 세 가지 생존 결말(제보를 갖춘 생존 / 방어의 흔적이 남은 생존 / 기본 생존)을 실제 제보·방어 사용 기록으로 결정하며 놓친 배송 수도 표시합니다.

## 체험실 등록 상황

| 분류 | 상황 |
| --- | --- |
| 방문 · 9개 | 정상 배송, 번호를 못 읽는 배달원, 이웃 우편물, 빈 복도, 주문 번호 사칭, 올바른 대답 사칭, 거짓 퇴장, 사각지대, 반복 노크 |
| 생활 · 14개 | 업무 중 초인종, 수면 중 초인종, 비축 식사, 좋아하는 음식, 회수 마감 직전, 도난, 배송 지연, 식량 없음, 일일 식사 실패, 취침 리듬 변화, 밤 산책·거부, 낮 산책, 공복 한계, 정신력 한계 |
| 조사 · 6개 | 손목, 차량, 카메라 배송·설치, 설치 후 녹화, 소급 녹화 불가, 제보·순찰 |
| 방어 · 6개 | 스프레이, 경보기, 손전등, 같은 수단 재사용 실패, 호신용품 배송, 무방비 조우 |
| 결말 · 3개 | 기본 생존, 증거를 갖춘 생존, 방어의 흔적이 남은 생존 |

날짜·시간대·정신력·식량·주문 여부·물품 종류·호신용품을 설정합니다. 결식 직전·정신력 한계·특정 배송·마지막 자정처럼 해당 상황을 성립시키는 필수 조건은 별도로 표시하고 불필요한 선택기를 숨깁니다. 호신용품이나 정신력을 바꾸면 같은 상황에서도 결과가 달라질 수 있습니다.

체험 중에는 자유 이동과 실제 상호작용을 사용할 수 있고, N 또는 ‘상황 진행’ 버튼으로 권장 행동을 바로 수행할 수도 있습니다. F5는 같은 조건으로 초기화, F6은 조건 화면, F7은 목록입니다. 문 개폐·조우·생활 동작 도중에는 중복 실행과 초기화를 막습니다. 결과 메뉴에서도 재시작·조건 변경·목록으로 돌아갑니다. 체험을 떠나 새 데모를 시작하면 자금·재고·기록·엔딩은 전부 데모 초기값으로 돌아갑니다.

## 구조와 검증

`scenario_catalog.gd`는 단일 상황 등록부와 초기 조건, 권장 행동을 정의합니다. `scenario_lab.gd`는 분류·조건 UI·재시작·내비게이션을 담당합니다. 체험 전용으로 성공·사망 플래그를 강제 설정하지 않으며 데모와 같은 `state.gd`, `full_game.gd`, `presence.gd`로 결과와 연출을 만듭니다.

`tests/test_scenarios.gd`는 38개 등록 항목의 생성과 실제 행동·실패·방어·결말, 조건 변경, 초기화 격리, 데모 준비 예산·5일차 지연·후반 사칭과 재방문을 검사합니다. `--test-lab`는 단일 메인 메뉴, Esc 경로, 모든 상황의 실제 관찰·생활·휴대폰 화면 구성, 조건 변경·재시작·실패 후 메뉴, 데모 초기화 격리를 검사합니다. `--capture-lab`로 메뉴·목록·조건·체험·결과·데모 휴대폰을 실제 렌더링해 확인합니다.

등록된 모든 상황 유형을 선택할 수 있는 시제품이며 모든 상태 조합이나 장기 밸런스가 플레이 테스트까지 완료되었다는 의미는 아닙니다. 새로운 상황은 등록부에 추가하고 같은 검증과 목록을 통해 확장합니다.
